# Yarubeshitara! (`yarube`) — やるべしたら！超軽量 CLI デイリー手帳

[English](README.md) | **日本語 (Japanese)**

**Yarubeshitara!（やるべしたら！）** は、ターミナルからワンライナーで素早く「**△ やることリスト**」と「**△ ふりかえり**」を記録・棚卸しできる、Rust 製の超軽量 CLI Todo ＆ ふりかえり手帳アプリです。

---

## 作った理由 (Why) と名前の由来

> 毎日使っている紙のメモ帳のような手軽さとより便利さが欲しくなって、作ってみた。完全自分向け！軽量と使い勝手を追求したTodoアプリ！

**なぜ `Yarubeshitara!` (`yarube`) ？**
北海道出身としての気持ちを込めて、北海道弁で「**よし、やろう！**」「**じゃあ、やろうか！**」を意味する温かく勢いのある言葉 **「やるべしたら！」（やるべ）** から名付けました。ターミナルで `yarube` と打ち込むたびに、思考を止めず軽やかにタスクへ踏み出せる相棒です。

---

## 特徴 (Features)

- **思考を止めないゼロ摩擦の記録（0.1秒以内）**
  - `yarube 明日の 会議 資料作成` のように記号やクォートを省略しても、そのまま当日の「△ やることリスト」へ `•` 付きで即座に追記され、手帳全体が `[NEW]` ハイライト付きで再描画されます。
  - 直前のタスクに対する補足メモも `yarube sub "Lubuntu -> Xubuntuが良いか"` でインデント（`  - `）として紐づけられます。
- **1日の終わりの1キー棚卸し ＆ 翌日への自動転記 (`yarube review`)**
  - 未完了タスク（`•`）を1件ずつ提示し、`o`（完了 `O`）/ `m` または `>`（翌日へ移行 `>`）/ `c`（取消 `~`）/ `s`（スキップ）の1キー操作でサクサク棚卸しできます。
  - 移行（`>`）を選んだタスクは、配下のサブ項目（`  - ...`）ごと翌日の手帳ファイルへ未完了タスク（`•`）として自動引き継ぎされます。
  - 1件確定するごとに即時保存されるため、途中で `Ctrl+C` 中断しても直前までの結果が消えません。
- **お気に入りのエディタで「△ ふりかえり」を書き殴る (`yarube reflect`)**
  - `yarube config editor` で VS Code（`code --wait`）や `nvim` / `vim` / `nano` など好きなエディタを設定可能。思いついた所感を自由にダンプできます。
- **手帳をめくる感覚のページ閲覧 ＆ キーワード全文検索**
  - `yarube prev`（または `yarube -1`, `yarube -2`）で、休日などの未記録日を飛ばして「直前に書いた記録日（1営業日前など）」の手帳をパッと開けます。
  - `yarube browse` で前後の記録日を矢印キー（`←` / `→`）や `p` / `n` キーでパラパラめくれます。
  - `yarube search <キーワード>` で過去すべての手帳から一致するタスクブロックやふりかえり行をハイライト抽出します。
- **4種の 24bit True Color カラーテーマ ＆ 文字化けゼロの安全な記号体系**
  - `tokyo-night`（デフォルト）、`monokai`、`nord`、`sepia` の4テーマを搭載。`yarube theme <name>` で即座に切り替えてプレビューできます。
  - Nerd Fonts や絵文字に一切依存せず、どの OS・端末でも崩れない標準 Unicode 記号（`•`, `>`, `O`, `~`, `-`, `─`, `△`）のみで構成されています。
- **日英バイリンガル対応 ＆ 外部クレート依存ゼロ**
  - `LANG` 環境変数や `yarube config lang en|ja` に応じて表示言語が切り替わり、日英どちらの見出しの Markdown ファイルも相互に読み書きできます。
  - 外部クレート依存ゼロ（Rust 標準ライブラリのみ）で実装されており、ビルドも実行も一瞬で完了します。

## 手帳のフォーマット例 (Markdown)

日々の記録は `~/.yarube/YYYY-MM-DD.md`（環境変数 `YARUBE_DIR` で変更可）にプレーンな Markdown として保存されます。

```markdown
### 10/17(火)

#### △ やることリスト
O SIT-1-1-1-001のテスト作る
> PodmanにGitbucketを立ち上げる
  - Lubuntu -> Xubuntuが良いか
• MCP用の変換ツール作成する
  - PDF -> Markdown化

#### △ ふりかえり
EndeavourOSにしたあき！
UXって大事。EndeavourOSでサクサク動き、Win11よりも軽いから使い勝手向上した。
本は格段に読みやすくなったので、勉強頑張ろう。
```

### ステータス記号の意味

| 記号 | 状態 | 説明 |
| :---: | :--- | :--- |
| `•` | 未完了 (Todo) | 新規追加されたタスク、および前日から引き継がれたタスク |
| `O` | 完了 (Done) | 完了したタスク（表示時は薄字＋取り消し線で視覚的に減衰） |
| `>` | 翌日へ移行 (Migrated) | 翌日の「△ やることリスト」へ引き継ぎ済みのタスク |
| `~` | 取消 (Cancelled) | 実行を取りやめたタスク（表示時は薄字＋取り消し線） |
| `  - ` | サブ項目 (Subtask) | 親タスクに紐づく補足メモ（移行時は親タスクと一緒に翌日へ転記） |

## インストール (Installation)

Rust ツールチェーン（`cargo` / `rustc`）があれば、外部パッケージのダウンロードなしで約1秒でビルドできます。

```bash
git clone <repository-url>
cd Bullet
cargo build --release

# パスの通ったディレクトリへ配置（例: ~/.local/bin）
cp target/release/yarube ~/.local/bin/yarube
```

## 使い方 (Usage)

### 1. 日中の記録・俯瞰

```bash
# 今日の手帳を表示（当日初回はテンプレートを自動生成）
yarube

# タスクを追記（'t' あり・なし両対応、クォート省略での複数単語も自動結合）
yarube t SIT-1-1-1-001のテスト作る
yarube 明日の 会議 資料作成

# 直前のタスクに補足（サブ項目）をぶら下げる
yarube sub "Lubuntu -> Xubuntuが良いか"
```

### 2. 夜の棚卸し・ふりかえり

```bash
# 未完了タスク(•)を1問1答・1キーで棚卸し
# [o] 完了(O) / [m または >] 翌日へ移行(>) / [c または ~] 取消(~) / [s または Enter] スキップ
yarube review

# エディタを起動して『△ ふりかえり』を自由に記述
yarube reflect

# 1行で直接『△ ふりかえり』に追記することも可能
yarube reflect 今日は集中してテストを書き切れた！
```

### 3. 過去の手帳をめくる・検索する

```bash
# 直前の記録日（休日を飛ばした1営業日前など）を表示
yarube prev     # または yarube -1
yarube -2       # 2記録日前を表示
yarube next     # 次の記録日を表示（または yarube +1）

# 対話モードで前後の記録日をパラパラめくる ([p/h/←] 前 / [n/l/→] 次 / [t] 最新 / [q] 終了)
yarube browse

# 全デイリーログからキーワード検索（一致箇所をハイライト表示）
yarube search EndeavourOS
```

### 4. カラーテーマ・エディタ・言語設定

```bash
# カラーテーマの切り替え＆即時プレビュー (tokyo-night / monokai / nord / sepia)
yarube theme monokai
yarube theme nord
yarube theme sepia
yarube theme tokyo-night
yarube theme              # 対話リストから選択

# ふりかえり用エディタの設定（優先度: 設定ファイル > $VISUAL > $EDITOR > nano/notepad）
yarube config editor
yarube config editor "code --wait"

# 表示言語の切り替え（日本語 / 英語）
yarube config lang ja
yarube config lang en
```

## アーキテクチャとテスト (Architecture & Tests)

高凝集・疎結合・テスト容易性を重視したレイヤード構成（Ports & Adapters）を採用しています。

- `src/domain/`: I/O に一切依存しないドメインロジック（日付計算、Markdown パーサー、設定・エディタ解決、ページ移動計算、全文検索、i18n、カラーテーマパレット）
- `src/ports.rs`: ストレージ・設定・外部エディタ起動の抽象トレイト定義
- `src/infra/`: ファイルシステム永続化（アトミック保存）および OS サブプロセス起動の実装
- `src/ui/` & `src/cli.rs`: 純粋関数による CLI 引数パーサー、True Color レンダラー、対話モード制御

```bash
# 単体テスト（14件）＋ BDD統合テスト（21件）の実行
cargo test
```

## コラム：このアプリの作り方（Antigravity × WDD）

このアプリケーションは、**専用のエージェントハーネスやカスタム Skills・ルール設定などを一切使わず**、**Antigravity** と **WDD（Why-Driven Development）** という要求定義手法の掛け合わせだけで開発されました。

[Requirements.md](Requirements.md) にある通り、Mermaid のマインドマップ形式で以下の階層を一本の木として構造化しています：

1. **US（ユーザーストーリー / Why）**: 誰が・何を・**なぜ**欲しいのか（手書きメモ帳の「△ やることリスト」と同じ低摩擦で思考を開示したい、など）
2. **AC（受け入れ基準）**: 満たすべきゴール条件
3. **TP（テスト観点）**: 正常系・境界値・障害回復性・視認性などの検証切り口
4. **BDD（振る舞い駆動開発）**: `Given / When / Then` による具体的な操作シナリオ
5. **EARS（Easy Approach to Requirements Syntax）**: イベント駆動型・状態駆動型・遍在型・不要動作型による曖昧さのないシステム要件記述

最初に `US-01`・`US-02` のコア体験を作って実際にターミナルで触り、そこから `US-03`（エディタ設定）、`US-04`（ページめくり・検索）、`US-05`（日英バイリンガル）、`US-06`（カラーテーマ）へと段階的に要求ツリーを育てながら、高凝集・疎結合な設計と全21観点（`TP-01`〜`TP-21`）の自動テストを一気通貫で作り上げています。
